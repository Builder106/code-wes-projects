## Runtime correction (Node 26, not Node 20)

Initial verification ran under the system Node (v20.20.2), reached over plain
`ssh ampere-dev "cmd"` without sourcing nvm. The controller flagged this:
ampere-dev's intended default is Node 26.7.0 via nvm, which non-interactive
SSH sessions don't source automatically. Redid all install/test steps with
`source ~/.nvm/nvm.sh && ...` prefixed, confirmed `node --version` → `v26.7.0`.

Redoing surfaced a **second, more important** problem the Node 20 run had
masked: Node's `--test` runner changed behavior for directory arguments
between v20 and v26. On v20, `node --test tests/` with an empty/missing
`tests/` reports 0 tests cleanly (once the `--test-name-pattern` flag is
reordered before the path — see below). On v26, the same invocation throws
`MODULE_NOT_FOUND` and exits 1, whether `tests/` is missing, empty, or holds
only a placeholder file — v26's runner falls back to `require()`-ing the
bare path as a test file when its directory scan finds zero matches.

Fix: use an explicit glob instead of a bare directory path. Final `test`
script:

```
node --test --test-name-pattern='^(?!.*Playwright)' 'tests/**/*.test.mjs'
```

Verified clean (0 tests, exit 0) under Node 26.7.0, with no `tests/`
directory present at all — the glob simply matches nothing, which is the
correct "no tests yet" state for this task. This also assumes later tasks'
unit test files will follow the `*.test.mjs` naming convention (Node's own
default discovery pattern); `.spec.mjs` files (the Playwright specs named in
`test:e2e`) won't be picked up by this glob, which is intentional — they run
only via `npm run test:e2e`.

(The earlier flag-reordering fix under Node 20, noted in a prior version of
this report, is superseded — under Node 26 flag order didn't matter, the
bare-directory-path issue did.)
